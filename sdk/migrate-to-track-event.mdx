In the new SDK versions, a payment is an in-app event with revenue. You send it with `trackPayment`, and it goes to the same pipeline as your other in-app events. `capturePayment` and `removePayment` are removed.

Apps on older SDK versions keep working with no change. Migrate when you upgrade.

| Platform | Package | Old versions (`capturePayment`) | New versions (`trackPayment`) |
| --- | --- | --- | --- |
| Android | `io.linkrunner:android-sdk` | 4.x | 5.0.0 |
| iOS | LinkrunnerKit | 4.x | 5.0.0 |
| React Native | `rn-linkrunner` | 3.x | 4.0.0 |
| Flutter | `linkrunner` | 4.x | 5.0.0 |
| Expo | `expo-linkrunner` | 3.x | 4.0.0, with `rn-linkrunner` 4.0.0 or later |
| Capacitor | `capacitor-linkrunner` | 2.x | 3.0.0 |
| Cordova | `cordova-linkrunner` | 1.x | 2.0.0 |
| Unity | [Unity bridges](/sdk/unity#track-payments) | Bridges on native 4.x | Bridges on native 5.0.0 |

<Warning>
  **Use the exact same event name, with the same spelling and letter case.**

  Your old payment `type` becomes the `eventName`. If you sent `FIRST_PAYMENT` before, send `"FIRST_PAYMENT"` now. Do not change it to `first_payment`, `First_Payment`, or `firstPayment`.

  Linkrunner matches the name exactly. A different spelling is treated as a new in-app event, so your existing Meta and Google mappings will not match it, and those payments will not be sent to Meta or Google.
</Warning>

## How to migrate

1. **Upgrade the SDK** to the new version in the table above.
2. **Replace `capturePayment` with `trackPayment`.** Rename `type` to `eventName` and keep the same value.
3. **Add `currency`.** It is required now, for example `"USD"` or `"INR"`.
4. **Remove `removePayment` calls.** There is no replacement.
5. **Test once** with a debug build and check the payment on the [Events](https://dashboard.linkrunner.io/dashboard/events) page under the same name as before.

## Old payment types

These are the old payment types. Send them exactly like this, in uppercase:

`FIRST_PAYMENT`, `SECOND_PAYMENT`, `TRIAL_STARTED`, `TRIAL_CANCELLED`, `WALLET_TOPUP`, `FUNDS_WITHDRAWAL`, `SUBSCRIPTION_CREATED`, `SUBSCRIPTION_RENEWED`, `SUBSCRIPTION_CANCELLED`, `SUBSCRIPTION_REFUNDED`, `SUBSCRIPTION_BILLING_ISSUE`, `DEFAULT`, `ONE_TIME`, `RECURRING`

If you did not pass a `type` before, your payments were saved as `DEFAULT`. Use `"DEFAULT"` as the event name. In Flutter, `PaymentType.DEFAULT_PAYMENT` was also saved as `DEFAULT`, so use `"DEFAULT"`, not `"DEFAULT_PAYMENT"`.

## What changes in the call

| `capturePayment` | `trackPayment` |
| --- | --- |
| `type` | `eventName`, same value and spelling |
| `paymentId` | `paymentId` |
| `userId` | `userId`, still required |
| `amount` | `amount`, the order total |
| `status` | `status`, optional, defaults to `PAYMENT_COMPLETED` |
| `eventData` | `eventData` |
| Not available | `currency`, new and required |

Only `PAYMENT_COMPLETED` payments count as revenue and are sent to ad networks. See [Payment status](/sdk/track-payments#payment-status) for the other statuses.

## Code examples

Each example keeps the old `FIRST_PAYMENT` name, so your mappings keep working. `eventData` with product details is optional. Send it only if you use [Meta Commerce Manager](/ecommerce-manager/meta-commerce-manager) or [Google Commerce Manager](/ecommerce-manager/google-commerce-manager).

<Tabs>
  <Tab title="Android">
    Before (Android SDK 4.x):

    ```kotlin
    val paymentData = CapturePaymentRequest(
        paymentId = "payment_123", // your order ID
        userId = "user123", // your user ID
        amount = 99.99, // total the user paid
        type = PaymentType.FIRST_PAYMENT, // becomes eventName in trackPayment
        status = PaymentStatus.PAYMENT_COMPLETED // same values in trackPayment
    )
    LinkRunner.getInstance().capturePayment(paymentData)
    ```

    After (Android SDK 5.0.0):

    ```kotlin
    import io.linkrunner.sdk.models.PaymentStatus

    LinkRunner.getInstance().trackPayment(
        eventName = "FIRST_PAYMENT", // was "type"; becomes the payment type in reports and mappings
        paymentId = "payment_123", // your order ID, used to deduplicate
        userId = "user123", // required, links the payment to your user
        amount = 99.99, // order total the user paid
        currency = "USD", // new, required: 3-letter ISO 4217 code
        status = PaymentStatus.PAYMENT_COMPLETED, // optional, default; only completed payments go to ad networks
        // Product details: Meta receives these fields, Google receives content_ids as item IDs
        eventData = mapOf(
            "content_ids" to listOf("sku_123"),
            "contents" to listOf(mapOf("id" to "sku_123", "quantity" to 1, "item_price" to 99.99)),
            "content_type" to "product",
            "num_items" to 1,
            "order_id" to "payment_123"
        )
    ).onFailure { error ->
        println("Error tracking payment: ${error.message}")
    }
    ```


    See [Tracking Payments](/sdk/android#tracking-payments) for the full reference.

## Using a new event name

You can use a new name such as `purchase` instead of an old type. Before you release, add a mapping for that name in the dashboard for Meta, Google, and any other partner that should get it. Without a mapping, the payment is saved in Linkrunner but not sent to ad networks.

Keep one name per payment. The same `paymentId` sent under two names counts as two payments.

## Already calling trackEvent?

You can attach the payment to an existing `trackEvent` call instead of calling `trackPayment`. Pass a payment object with `amount`, `paymentId`, `currency`, `userId`, and an optional `status`. The same naming rule applies. Each SDK page shows this under **Tracking Payments**.

## Sending payments from your server

Use `POST /api/v1/capture-event` with `amount`, `payment_id`, and `currency` next to `event_name` and `user_id`. The same naming rule applies. See [Events Capture API](/api-reference/event-capture#payment-fields). `POST /api/v1/capture-payment` is deprecated but keeps working.
