In the new SDK versions, a payment is an in-app event with revenue. You send it with `trackEvent`, the same method you use for custom events. `capturePayment` and `removePayment` are removed.

Apps on older SDK versions keep working with no change. Migrate when you upgrade to the [versions below](#sdk-versions).

<Warning>
  **Use the exact same event name, with the same spelling and letter case.**

  Your old payment `type` becomes the event name. If you sent `FIRST_PAYMENT` before, send `"FIRST_PAYMENT"` now. Do not change it to `first_payment`, `First_Payment`, or `firstPayment`.

  Linkrunner matches the name exactly. A different spelling is treated as a new in-app event, so your existing Meta and Google mappings will not match it, and those payments will not be sent to Meta or Google.
</Warning>

## Before and after

The old `capturePayment` call, then the same payment with `trackEvent`. The product keys are optional: Meta receives `content_ids`, `contents`, `content_type`, `num_items`, and `order_id`, and Google receives `content_ids` as item IDs. `amount` stays the order total.

    Before (Android SDK 4.x):

            "amount" to 1200.0,
            "paymentId" to "bk_10231",
            "currency" to "INR", // new, required
            "userId" to "playo_u_8842",
            "status" to "PAYMENT_COMPLETED", // optional, the default
            // product details for Meta and Google
            "content_ids" to listOf("court_c2_1800"),
            "contents" to listOf(mapOf("id" to "court_c2_1800", "quantity" to 1, "item_price" to 1200.0)),
            "content_type" to "product",
            "num_items" to 1,
            "order_id" to "bk_10231"
        )
    )

## How to migrate

For each `capturePayment` call, make three edits:

1. **Rename `capturePayment` to `trackEvent`.**
2. **Pass your old `type` as the event name,** the first argument, with exactly the same spelling.
3. **Move the payment fields into the event data:** `amount`, `paymentId`, `userId`, and `status` keep their names. Add `currency`, which is new and required, for example `"USD"` or `"INR"`.

Then remove every `removePayment` call, and test once with a debug build. The payment should show on the [Events](https://dashboard.linkrunner.io/dashboard/events) page under the same name as before.

| `capturePayment` | `trackEvent` |
| --- | --- |
| `type` | the event name (first argument), same value and spelling |
| `amount` | `amount` in the event data, the order total |
| `paymentId` | `paymentId` in the event data, required |
| `userId` | `userId` in the event data, still required. An empty string uses the user saved by `signup` or `setUserData` |
| `status` | `status` in the event data, optional, defaults to `PAYMENT_COMPLETED` |
| `eventData` | the other keys in the event data, such as product details |
| Not available | `currency` in the event data, new and required |

The event is a payment only when the event data has `amount`, `paymentId`, and `currency` together. If any of the three is missing, it is not a payment:

- `amount` or `currency` without `paymentId` is a normal custom event, exactly as before.
- `paymentId` with `amount` or `currency` missing is an error, and nothing is sent.

Only `PAYMENT_COMPLETED` payments count as revenue and are sent to ad networks. See [Payment status](/sdk/track-payments#payment-status) for the other statuses.

## Old payment types

These are the old payment types. Send them exactly like this, in uppercase:

`FIRST_PAYMENT`, `SECOND_PAYMENT`, `TRIAL_STARTED`, `TRIAL_CANCELLED`, `WALLET_TOPUP`, `FUNDS_WITHDRAWAL`, `SUBSCRIPTION_CREATED`, `SUBSCRIPTION_RENEWED`, `SUBSCRIPTION_CANCELLED`, `SUBSCRIPTION_REFUNDED`, `SUBSCRIPTION_BILLING_ISSUE`, `DEFAULT`, `ONE_TIME`, `RECURRING`

If you did not pass a `type` before, your payments were saved as `DEFAULT`. Use `"DEFAULT"` as the event name. In Flutter, `PaymentType.DEFAULT_PAYMENT` was also saved as `DEFAULT`, so use `"DEFAULT"`, not `"DEFAULT_PAYMENT"`.

## Refunds and removePayment

`removePayment` is removed and has no replacement. To record a refund or a cancelled booking, send the same event name and `paymentId` again with `status` set to `PAYMENT_CANCELLED`. That payment no longer counts as revenue, and nothing is sent to ad networks.

## Using a new event name

You can use a new name such as `purchase` instead of an old type. Before you release, add a mapping for that name in the dashboard for Meta, Google, and any other partner that should get it. Without a mapping, the payment is saved in Linkrunner but not sent to ad networks.

Keep one name per payment. The same `paymentId` sent under two names counts as two payments.

## Sending payments from your server

Use `POST /api/v1/capture-event` with `amount`, `payment_id`, and `currency` next to `event_name` and `user_id`. The same naming rule applies. See [Events Capture API](/api-reference/event-capture#payment-fields). `POST /api/v1/capture-payment` is deprecated but keeps working.
